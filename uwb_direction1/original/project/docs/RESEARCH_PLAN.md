## 0. 先读这一段:三个名词的大白话解释

后面会反复用到三个词,先用人话讲清楚,免得"具体了反而不懂"。

**(1) 跨视角掩码重建(就是 F3 / B2 在做的事)。**
把三个雷达里的**一个**藏起来,让模型用另外两个去**重建**被藏的那个的回波。
为什么有用:要重建出"左雷达会看到什么",模型必须先搞懂"同一只手的运动,在左/上/右
三个角度下分别长什么样"——也就是三视角之间的几何关系。**这是我们四个负结果
(E4/E5/F0/F1)反复证明"分类任务学不出来"、而 B2 早筛正面证明"重建任务学得出来"的
那层几何。** 训练完之后有一个免费的副产物叫 `e_recon`(重建误差):
- 已知手势 → 三视角天然自洽 → 重建得好 → 误差低;
- 未知手势 → 三视角对不上 → 重建得差 → 误差高。
于是"重建误差高不高"本身就是一个"这是不是没见过的手势"的探测器。
**注意它和现在的 inspector 是两种完全不同的东西**:inspector 是"分类器 + 拒识按钮",
e_recon 是"模型学会了正常手势长什么样,凡是不像的就报警"。后者是单视角原理上
造不出的信号(单视角没有"其余视角"可对照)。

**(2) 潜在运动状态 z(t)(论文二的核心升级)。**
不直接重建回波,而是先让模型把"这一刻手在怎么动"压缩成一小串随时间排列的向量
z(t),再从 z(t) 解码出各视角回波。z(t) 就是"手的运动假设"的数学表示。
好处:① 可以画出来(画圈手势的 z(t) 真的应该是个圈);② 手势的属性(往左、往上、
有没有旋转)在 z(t) 里应该是**线性可读**的,这是论文二"描述未知手势"的地基。

**(3) JEPA / EMA teacher(一个修 bug 的技术,不是新坑)。**
你在 RESULTS §18 自己标注了一个 caveat:如果让模型去预测"另一份自己算出来的特征",
容易**坍缩**(模型偷懒,把所有东西都预测成同一个常数)。LeCun 的 I-JEPA/V-JEPA 早就
有标准解法:用一个**缓慢更新的影子模型(EMA teacher)**当预测目标。这是个现成的补丁,
不是要你发明新东西。**论文一可以完全不碰它**(论文一用"重建原始回波",没有坍缩风险);
它只在论文二需要干净的 z(t) 时才登场。

## 3. 论文二:从"拒识未知"到"描述未知"

**标题方向**:《Compositional Open-Set Gesture Interpretation: Describing Unseen
Gestures via a Latent Motion Model》

> ⚠️ **这是冒险的一篇,高上限高风险。它必须等论文一的脊柱立住、且 S1 早筛开绿灯
> 才启动。** 如果 S1 红灯或 S2 的 latent 路线不顺,直接走第 4 节的论文三(保险)。

### 3.1 新任务:open-set recognition → open-set interpretation

系统遇到词表外手势时,不再只说"未知",而是输出一个**属性元组**:
"未知手势:向左 + 向上滑动,无旋转,无推进"。

**为什么 12 类够用(破解"零样本统计力不足")**:评测不在 12 类层面,而在**属性层面
做组合泛化**(CZSL 标准协议)。你的词表天然是一张属性网格:
- G1–G4 = 四个正交滑动(L→R, R→L, U→D, D→U);
- **G5–G8 = 四个对角滑动 = 正交分量的两两组合**(左上 = 向左 ⊗ 向上);
- G9/G10 = 顺/逆时针,G11 = 推,G12 = 空。

干净的 split:**训练只给正交滑动(模型见过"向左"和"向上",从没见过"向左且向上"),
测试考四个对角(未见组合)**。每个属性值有上千样本支撑,统计力没问题;对角恰好 4 个,
还能做"留一对角"4 折。

### 3.2 核心升级:潜在运动轨迹 z(t) + JEPA

论文二才需要干净的 z(t)(论文一用 raw 重建不需要):
- 把 B2 的瓶颈/token 升级成**一条潜在轨迹 z(t)**;
- 用 **JEPA(EMA teacher)** 做潜空间预测,解决 §18 标注的坍缩 caveat;
- 解码器以**雷达坐标为条件**——把 FUSION_DESIGN §6 的"可学习软三边定位"从隐喻变成结构。
- **"JEPA on RF sensing"目前没人做**,这是一个干净的方法迁移点。

**两根柱子互为验证**:属性(方向、旋度)若在 z(t) 里线性可读 → 组合泛化才可能成立;
反过来,组合泛化成不成立,直接检验 z(t) 是不是真的编码了运动几何。

### 3.3 应用闭环(柱三:少样本注册 + 可信阈值)

- **少样本注册**:新手势 = 在 z(t) 空间挂一个新原型 + 新 inspector。你的 per-class
  架构**天生免遗忘**(加新类不动老类),这个卖点不变;
- **注册用属性/文本初始化原型**(柱二提供接口),用三视角一致性去噪(脊柱提供)——
  语言对齐从"危险主线"降级成"属性空间的一个免费接口",风险被属性层评测兜住;
- **conformal(共形预测)给每类拒识阈值套覆盖率保证**。这顺带回应你 §15/§17 自己
  发现的"η=3 不跨尺度迁移"——你已用实验证明启发式阈值不可靠,conformal 就是这个
  发现的方法论答案。**A7 两节直接变成 conformal 章节的 motivation,一字不浪费。**

## 4. 论文三(保险,不依赖生成模型,随时可独立成篇)

**标题方向**:《Few-Shot Gesture Registration with Calibrated Open-Set Rejection
for UWB Radar》

不依赖生成模型,只用现有 inspector 架构(本就免遗忘):
**少样本新手势注册(FSCIL)+ conformal 可信拒识**。它既是论文二的应用闭环(柱三),
也能完全独立成篇——即使柱二(组合)失败,柱三 + 论文一的脊柱也能拼出一篇,
**不存在"全盘皆输"**。2026-06-28 决定:论文二感觉不稳,先把这条作为下一篇主攻。

### 4.0 一句话故事

开集系统现在只会"拒识未知"。论文三让它再多一个能力:**用户给几个样本,就能把一个
新手势"注册"成正式一类**,以后认得出来,而且① 不忘老手势、② 仍能拒掉真正没注册过的
手势、③ 不重训编码器(能在端上做)。卖点不是性能更高,而是**这套能力几乎是现有架构的
免费副产物 + 一个有覆盖率保证的拒识阈值**。

### 4.1 为什么你的架构天生适合(大白话 + 比喻)

现在的开集头像个**带名单的门卫**:名单上 6 个名字(6 个 known 类),每个名字配**一张独立
人脸卡**(每类一个 inspector + 原型 φ_k + 阈值 σ_k,见 `uwb_osr/inspector.py`)。
来人 → 先猜你是名单上谁 → 拿对应人脸卡核对 → 不像就轰走。

"注册新手势" = **给门卫看几张新人照片(few-shot),往名单加一个名字,但不重训门卫对所有
老人的认识**。为什么顺:每类是一张独立的卡,加第 7 张卡前 6 张一字节不动 → **结构上天然
免遗忘**(FSCIL 最头疼的"学新忘旧"对这套架构不存在)。代码里 `train_inspector()` 现在
就是"某类正样本 + 其余负样本训一张卡",注册新类 = 拿新手势的几个样本当正样本再调一次,
几乎现成。

### 4.2 必须解决的设计点(也是方法部分的技术核心)

**当前"先猜名单内是谁"那步会卡死新类**:闭集分类器只有 6 个输出
([inspector.py](uwb_osr/inspector.py) 里 `pred = logits.argmax(1)`),新手势必被猜成
某个老类,再核对失败被当陌生人轰走,**永远当不成第 7 类**。

解法 = **把"先猜再核对"换成"跟所有人脸卡比,挑最像的"**(最近原型分类):
- 对每个类 k(老的 + 新注册的)算归一化距离 r_k = mean_v(d_k^v)/mean_v(σ_k^v)
  ("你离这个类有几个标准差");
- 预测 = argmin_k r_k;若**连最近的都太远**(min r_k > τ)→ 才判未知。
- 这套距离比较对"加新类"天然开放,加一个原型多一个候选,不碰分类器头。
  `anomaly_scores()` 已在算每类 d_k/σ_k,改成取 argmin 当预测即可。

> ⚠️ 每个 inspector 是独立 MLP,φ_k 活在各自的潜空间,**但 d_k/σ_k 是各自空间内的
> 归一化距离,可横向比较**("哪个类觉得你最不异常")。这点先在 N1 验证(换路由后 base
> 准确率不能塌)。

### 4.3 唯一的真难点:few-shot 本身(消融即卖点)

几个样本训 1024 宽 MLP 容易过拟合。两条路线做对照:
- **方案 A(同构)**:复用 `train_inspector` + 已有增广(高斯抖动正样本、mixup 负样本,
  `_augment` 现成)。和老类同构。
- **方案 B(NCM)**:新类不训 MLP,φ = 几个样本特征均值,在冻结特征空间比距离。极少样本
  (K=1)时更稳。
- A vs B 随 shot 数(K=1/5/10/20)怎么变,本身就是一张图。

### 4.4 conformal 加了什么 + 为什么是现成论据

现在判未知靠固定 η=3(3σ)。**你在 A7(§15/§17)已用实验证明这个固定阈值不跨尺度
迁移**——这正是 conformal 要解的问题。conformal 用一个校准集,给"多近算够近"配上
**覆盖率保证**("真标签有 1−α 概率落在我给的候选集里"),输出一个**候选集合**(空=拒识、
单个=确定、多个=纠结)。**A7 两节一字不浪费,直接变成 conformal 章节的 motivation。**

### 4.5 协议

12 类里挑 6 类当 **base**(在 7 个训练被试上训编码器,同主协议);从剩下 6 类挑 3 类当
**待注册新类**,用**训练被试的少量样本**注册;剩 3 类**始终不注册当真未知**。全程 **LOSO**
(在留出被试身上测 base+新类识别 + 真未知拒识)——即"开发者用实验室数据注册新手势、
部署到没见过的新用户"的现实场景。变体(personalization):shot 取自测试被试本人,
测同人更多样本(留作 N3 的 nice-to-have)。

### 4.9 N3 细化计划:修新类 conformal 覆盖(2026-06-30,综合 GPT 建议 + 我的判断)

> ⚠️ **本节已被实验结果部分推翻,现行计划见 §4.10**(2026-07-03):P1.5 balanced ✅ 兑现
> (+17.5);P1 hybrid 跑出 82.9(oracle 也到不了 90);**P2 σ-shrinkage 被证伪**(λ 越大越差,
> 破案:σ 反而偏大 1.5×,真病根是 d 膨胀 8~10×=少样本头的跨人转移差距,见 RESULTS §33.3)。
> 本节保留作过程记录。

N2(§32)定位:base 类覆盖率保证已恢复(global 89.7≈90%),**新类只有 49%**——根因是
新类 σ 只由 5 个 support 估,被低估 → 归一化距离 r=d/σ 被放大(新类到自身原型距离 ~12×
base) → base 校准的阈值覆盖不到新类。

**关键战略区分(我对 GPT 方案的最重要修正)**:hybrid 与 σ 校正回答两个不同的部署问题,
决定论文怎么写——
- **hybrid(用校准被试的新类样本单独定阈值)**:前提是**校准队列做过这个新手势**。对
  "已知候选词表"成立,对"用户自创全新手势"不成立。**定位 = 可达上界 / oracle**。
- **σ 尺度校正 / shrinkage(不需要任何新类校准数据)**:对真正全新手势也成立。**这才是
  论文的算法贡献,应与 hybrid 并列为头号,而非 GPT 的 P2 次级。**

故事线:注册框架(N1)→ conformal 给 base 覆盖保证(N2)→ 新类:有校准数据时 hybrid 补齐
(上界);没有时,用 base 类学到的少样本 σ 校正补齐大部分(贡献)。

**重排优先级(我的判断)**:

| 优先级 | 做什么 | 理由 | 成本 |
|---|---|---|---|
| **P1(在跑)** | hybrid conformal(base 用 global,新类用校准被试新类样本定阈值) | oracle 上界,确认框架。`n3_calib.bat` 跑的就是这条 | 已在跑 |
| **P1.5(提前)** | **subject-balanced support**:5 shot 强制来自 5 个不同人 | 直击病根(同人 5 样本方差天然偏小→σ 低估),几乎免费,两 regime 都受益 | 改 split + 1 跑 |
| **P2(贡献)** | σ 校正:base 上模拟 5-shot 学低估因子 a₅ 套到新类 σ;**等价于 σ-shrinkage λ:0→1 扫**(λ=1 即新类用 base 池 σ 尺度),不需新类校准数据 | 比 hybrid 更硬的贡献;且**大多后处理**(dump 每类 σ̄_k 即可,r*=r·σ/σ*) | 后处理为主 |
| **P3** | (并入 P2)shrinkage λ 扫为 σ 校正的可辩护实现 | — | 后处理 |
| **P4** | 新类 inspector 加 hard negative(其他新类 support) | register=[0,2,3] 同轴反向易混,次要 | 改几行 |

**全程盯 `reject_unknown` 别塌**(覆盖率拉高不能靠把未知全放进来)。

**效率设计**:下一跑 dump 每类 σ̄_k + 所有距离矩阵 → **shrinkage(λ 扫)/hybrid/global 全后处理**,
不重训。只有 subject-balanced support、hard-negative 改训练需实跑(合并进一个消融跑)。
当前 hybrid 跑用**随机 support**,消融跑用 **subject-balanced**,两者对比即得 P1.5 效果。

**基础设施**:2026-06-30 会话频繁重启,~30min 杀后台跑(三种启动法均中招;非代码 bug,死在
和 N1/N2 相同的编码器训练段)。对策:**消融跑编码器降到 ~30-40 epoch**(conformal 覆盖率与
编码器质量无关,校准结论成立;只识别准确率偏低,非考点)→ ~40-60min 跑完、可重试。
**headline 全配置跑**最稳是在独立终端跑 `n3_calib.bat`。脱离会话的 .bat 必须
`PYTHONUNBUFFERED=1`+`-u`(否则日志缓冲像卡死)。

**N3 新增代码**:`data.py: register_split_conf(subject_balanced=)`;
`registration.py: register_and_score` dump `sigma_bar` + 后处理 σ-shrinkage;
`main.py: --support-balanced`;后处理分析脚本(从 npz 算 global/hybrid/shrinkage-λ)。

### 4.10 修订方案:先表征后校准(2026-07-03,依据 RESULTS §33/§34)

**两个实验事实改写了优先级**:① §33.4 泄漏分解——被放进来的未知 53% 从 base 列漏入,
且 own-r vs 未知的 AUROC 只有 86.5/90.5,**校准只能沿覆盖-拒识边界滑动,挪边界必须改分数**;
② §34 误差解剖——同人注册 91.1 vs 跨人 75.2,**"换人"占新类误差的 2/3**。加上依赖关系
(所有 conformal 分位数都从当前编码器的距离分布算出,**编码器一换校准全部重做**),
正确顺序是**先把表征/分数做定,最后一次性校准**:

1. **表征阶梯(现阶段主攻,一晚一变体,统一评测协议=注册+conformal 全 dump)**:
   N4a B2-init(跨视角掩码重建预训练,吃论文一资产,零新建模)→ N4b episodic /
   N4c 被试对抗(梯度反转,对 subject shift 最对症),单独跑谁赢再叠加。
   **止损**:最多 6 变体/两周夜跑;acc_new≥80 或 AUROC≥83 即收手;全不中则 75.2 写成 finding。
2. **分数升级**:e_recon⊕r 融合非合规分数(堵 base 列泄漏,§28.6 有 +3.42 先例)+
   逐视角 p 值合并(需 dump 逐视角 r)。
3. **校准收官(在胜出编码器上一次做完)**:模拟任务共形(base 类当辅助任务排练 5-shot 注册,
   校准被试量膨胀分布 → few-shot 头专用阈值,替代已死的 shrinkage;不需任何新类校准数据)
   + hybrid(oracle 上界)+ 多/轮换校准被试。
4. **协议补全**:多 reg case、shot 曲线(1/5/10/20 + 5人×1 vs 1人×5)、personalization
   已有(§34,顺手成了部署卖点:global 阈值双向中靶 89.5/91.0)。

**论文三故事线(更新)**:机制(N1)→ 保证(N2)→ 诊断(N3:σ 神话破除、d 膨胀、泄漏分解、
balanced 采集指南)→ 归因(N4:换人占 2/3;同人场景已解决)→ 表征修复(N4a-c)→
数据无关校准(模拟任务共形)+ 场景配对的阈值方案(跨人 hybrid / 同人 global)。
