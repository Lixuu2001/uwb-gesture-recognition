# MVOSR 论文 Figure 2 重绘设计说明

**状态：** 方案已于 2026-08-06 在对话中确认，等待用户审阅本说明后实施。  
**范围：** 只设计并制作 Figure 2 的视觉母版、可编辑 PPTX 与预览文件；本阶段不替换论文现图、不修改正文、不改代码与实验。

## 1. 图的唯一叙事重点

Figure 2 只回答一个问题：**三种多视角融合策略的区别发生在哪里。**

- F2：编码器中层，在时间路径和距离路径内进行跨视角交换。
- F1：编码完成后，仅时间 token 跨视角交换；距离路径保持各视角独立。
- 本文方法：特征和距离估计阶段均不跨视角交换，只在最终决策端聚合三视角距离。

完整训练、原型构造和开放集判定只保留必要的缩略流程，不能抢占“融合位置”这一主视觉重点。

## 2. 画布与信息层级

- 横向双栏论文图，目标宽度约 183 mm。
- PPTX 画布暂定为 13.33 × 6.10 in，宽高比约 2.19:1。
- 整体采用“上方主流程 + 下方三策略对照”的两层结构。
- 主流程约占高度 58%，三策略对照约占 34%，上下留白和图注安全区约占 8%。
- 阅读顺序由一条连续的粗主箭头建立；次级连接线明显更细。
- 从主流程的三个真实位置分别向下发出粗蓝色引导箭头，准确落到 F2、F1、本文方法三个局部放大框。

## 3. 真实数据与可追溯性

### 3.1 数据样本

- 数据源：公开 UWB-Gestures 数据集。
- 固定样本：`HV1 / G1 / repetition 10`。
- G1 为左右挥动手势，和数据集原始绘图脚本的示例一致。
- 三个矩阵使用同一次重复的同步 `Left / Top / Right` 视角，禁止从不同样本拼接。
- 后续展示的代表矩阵 `X_v`、横向切片和纵向切片均从这组三视角矩阵中的同一真实样本派生。

### 3.2 矩阵语义

- 每视角输入尺寸：`T × M = 90 × 189`。
- 横轴：距离单元/快时间，189 个采样点，对应约 1.2 m 距离窗口。
- 纵轴：慢时间，90 帧，对应约 4.5 s。
- 论文图展示模型实际使用的 `abs-std` 表示，不使用 GPT Image 伪造矩阵。
- 三视角必须使用相同 colormap 和同一尺度。尺度优先使用三视角合并后的稳健分位范围，以避免单个离群值压扁主体纹理；最终参数写入生成脚本或元数据。
- 不在矩阵内部生成大段文字，仅保留必要的 `L / T / R` 与轴向图标，精确中文标签在 PPTX 中叠加。

## 4. 左侧采集场景

左侧采用简洁、平面化但有真实依据的科研插画，承担“为什么是三个视角”的解释：

- 左、右雷达水平相距 1.1 m。
- 顶部雷达位于水平中点上方 0.55 m。
- 手势发生在三雷达围成的中央工作区。
- 用一条清楚的左右双向手势轨迹表示 G1。
- 雷达朝向、测量波束和手部位置要有因果关系，不能画成任意三角装饰。
- 场景插画可以是 GPT Image 生成的独立 raster，但不包含难以校正的文字。

## 5. 上方主流程

从左到右依次为：

1. **三视角采集场景**：真实几何 + G1 左右挥动。
2. **三视角真实 CIR 输入**：并排显示 `X_L, X_T, X_R`。
3. **标准化输入**：简洁标注 `abs-std`。
4. **双路径编码**：用一个放大的真实 `X_v` 解释两种切割方式。
   - 横向逐行切割：时间路径，90 个 token，每个 token 为 189 维。
   - 纵向逐列切割：距离路径，189 个 token，每个 token 为 90 维。
   - 两路先线性映射到 `D = 32`，再分别通过 4 层 Transformer。
   - 两路输出展平并拼接为 `f_v ∈ R^8928`。
5. **视角内开放集距离**：三个视角分别输出 `d_L, d_T, d_R`。
6. **紧凑决策端**：只保留分类预测选择对应类别/视角 inspector，以及三距离聚合得到已知/未知判定；不展开后续训练细节。

主流程中的编码模块不画成一个巨大的“融合块”。其内部应清楚保留两条平行路径，三种融合位置通过局部放大图说明。

## 6. 下方三策略局部对照

三个面板必须使用完全一致的 `L / T / R` 输入、尺寸、模块顺序和视觉比例。差异只通过蓝色高亮区域和跨视角连线的位置体现。

### 6.1 F2：编码器中层融合

- 时间路径和距离路径各自拥有独立的 4-token bottleneck bank。
- 在 Transformer 中层进行跨视角信息交换。
- 画出两组小型 bottleneck token：`B_t × 4` 与 `B_r × 4`。
- 总编码深度保持不变，不能误画成额外串联的新编码器。
- 蓝色高亮位于编码器中部，强调“早于完整特征形成”。

### 6.2 F1：编码后特征融合

- 三视角各自完成双路径编码。
- 仅时间路径输出 token 在对应慢时间位置上跨视角交换。
- 距离路径从各自编码器直接旁路到视角特征，不发生交换。
- 蓝色高亮位于时间路径编码器之后、展平拼接之前。
- 禁止画成时间和距离两路都参与的通用 feature fusion。

### 6.3 本文方法：决策端聚合

- `X_L, X_T, X_R` 从输入到视角特征、再到各自 inspector 距离，全程没有跨视角连接。
- 只有 `d_L, d_T, d_R` 在最右侧汇聚为最终异常分数/已知未知判断。
- 蓝色高亮只出现在距离输出后的聚合节点。
- 该面板应是三者中视觉最简洁的一项，以突出“延迟融合、保留视角独立性”。

## 7. 视觉系统

### 7.1 风格原则

- 参考 CVPR 顶会流程图的学术图形语法：真实输入缩略图承担说明，粗箭头建立阅读方向，局部浅色底突出核心机制。
- 白底、深色线条、低饱和配色、明确的粗体标签。
- 模块优先使用无框布局、直角框或极小圆角；避免大量圆角卡片、胶囊按钮、渐变和发光效果。
- 不使用彩虹配色。颜色仅编码信息角色，不作为装饰。

### 7.2 固定色板

- 主文字/结构线：深海军蓝 `#17243A`
- 主强调蓝：`#2F80C9`
- 浅蓝机制底：`#DDEFF8`
- 时间路径：低饱和珊瑚色 `#C96B5C`
- 距离路径：低饱和蓝 `#3A7CA5`
- 中性浅灰：`#F2F3F5`
- 画布：`#FFFFFF`

### 7.3 字体与线条

- 中文：微软雅黑或思源黑体；英文和数学变量：Arial/Arial Math 类兼容字体。
- 面板标题使用粗体，正文只保留短语。
- 主流程箭头宽度约为次级连接线的 2 倍。
- 跨视角连接统一使用主强调蓝，普通数据流使用深海军蓝。

## 8. GPT Image 视觉母版约束

GPT Image 只负责生成整体构图与真实感较好的采集场景视觉，不负责生成科学矩阵和最终文字。

- 输入给 GPT Image 的矩阵区域使用已渲染的真实 CIR 图作为参考/后续替换目标。
- 提示词要求极少文字，预留干净标签位；不让模型生成中文长句、公式或数值。
- 明确禁止伪造热力图、装饰性网络纹理、厚重阴影、发光、3D 塑料卡片和 AI 信息图风格。
- 生成后先核对版式和视觉重心，再进入 PPTX 重建。

## 9. PPTX 重建约束

- 使用可编辑的原生 PowerPoint 形状重建模块、框、箭头、引导线、标题与所有中文标签。
- 真实 CIR 矩阵作为高分辨率 raster 嵌入；采集场景插画可作为独立 raster 嵌入。
- 不将整张 GPT Image 直接铺成不可编辑背景。
- 连接线必须先于节点创建，保证视觉上位于节点下层。
- 所有箭头均使用 PowerPoint 原生连接线，避免手绘线在编辑后断裂。
- 最终应能单独移动三个策略面板、替换任一真实矩阵、修改任一中文标签。

## 10. 质量检查

### 科学一致性

- [ ] 三个真实矩阵来自同一 `HV1/G1/repetition 10`。
- [ ] `X_v` 与所有切片来自同一实际矩阵。
- [ ] 时间路径为 90 个 189 维 token；距离路径为 189 个 90 维 token。
- [ ] `D=32`、4 层 Transformer、`f_v ∈ R^8928` 标注正确。
- [ ] F2 两条路径均在中层通过各自 4-token bottleneck 跨视角交换。
- [ ] F1 只有时间路径在编码后跨视角交换，距离路径旁路不交换。
