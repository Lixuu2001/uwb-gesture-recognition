## 1. r4 的两类问题

### 1.1 重复（用户已指出）

r4 把完全相同的东西画了三遍：

| 重复项 | r4 中的份数 | 应有份数 |
|---|---:|---:|
| CIR 位图 | 9 个对象 / 3 个唯一文件 | 3 |
| 「共享参数编码器 Eθ」框 | 3 | 1 |
| L/T/R 文字标签 | 9 | 3（一次图例） |
| 「逐视角检查器 / 判决」框 | 3 | 1 |
| 三路视角轴骨架 | 3 | 3（保留，见 §2） |

注意：三条视角轴的**骨架**必须保留三份，它是三栏的共同坐标系；要删的是
**信息密度高、内容逐字相同**的那些对象（位图、编码器定义、检查器定义、图例）。

### 1.2 与论文不符（新发现，比重复更要紧）

按 `paper1/mvosr_paper.tex` §3.2–§3.4、§5.3 与 `uwb_osr/model.py` 核对：

1. **(c) 栏「编码器 Eθ·后半段」画错了。** 代码里
   `TransformerPath` 是 `indep = depth − K` 层独立 + **最后 K 层**为
   `BottleneckFusionLayer`，正式配置 K=1、N_B=4（RESULTS §22.1）。瓶颈层
   **就是编码器的最后一层**，其后没有任何「独立后半段」。r4 画成
   瓶颈 → 编码器后半段 → 检查器，是事实错误。
2. **(b)/(c) 栏丢了最终判决式。** 三种策略最后都走同一个
   式 (12) `s = mean_v(d_v)/σ̄ + β·var_v(d_v)/σ̄²`。r4 只在 (a) 栏画了
   `mean + β var`，(b)(c) 栏止于「逐视角检查器/判决」，读者会误以为
   距离聚合是 (a) 独有的机制。实际关系是：**(b)(c) 是在共同管线上额外插入
   一次更早的交换**，而不是替换掉决策级聚合。
3. **缺闭集分类头与 k̂。** 检查器是 `η_k̂^(v)`，由阶段一的预测类 k̂ 选定。
   r4 从特征直接到 d_v，看不出检查器是类条件的。
4. **缺 σ 归一化。** 图上写 `mean + β var`，论文式 (12) 两项分别除以
   σ̄ 与 σ̄²。
5. **视角嵌入 e_v 的位置误导。** r4 只在 (c) 栏写「视角身份已注入」，像是
   MBT 专有。实际上主架构在特征码上加 `e_v`（`SharedDualPathEncoder.view_emb`），
   而 MBT 额外在 **token** 上加 `view_emb_tok` 破置换对称，是两处不同的东西。
6. **(b) 与 (c) 的双路径不对称没画出来。** `CrossViewFusion` 只作用在
   **时间路径 token**（`model.py` 注释：spatial path has no post-encoder
   cross-view stage）；MBT 则 temporal/spatial **两条路径都融合**。论文把
   「两条路径都参与」写成 MBT 的修复点之一，图上却只在 (c) 标了这句，
   没有建立与 (b) 的对照，读者看不出这是差异。
7. **没有结果数字。** 图与表 `tab:fusion` 分离，图本身不承载结论。

### 2.1 顶会图的设计依据

这一版式的三条规则都有直接出处：

- **同一骨架，只让连线拓扑变化。** MBT（Nagrani et al., NeurIPS'21）Fig. 2
  比较 late / early-concat / mid / bottleneck 四种融合，四个面板用完全相同的
  层栈网格，只改 token 之间的连接方式，不重复任何输入样本。EfficientDet
  Fig. 2 比较 FPN / PANet / NAS-FPN / BiFPN 同理：同一套 P3–P7 节点网格，
  只有边不同。**本文 (c) 栏的机制正是 MBT，沿用其图语法也最不容易被误读。**
- **重的东西画一次，轻的骨架可以重复。** 上述论文都不重复数据样本、不重复
  模块定义文字；共享词汇（层、token、模态）在图例或最左侧标一次。
- **「我们的」放最后一栏。** MBT 的 bottleneck、EfficientDet 的 BiFPN 都是
  最后一个面板。本设计据此把栏序改为按交换深度由浅到深，(c) = 本文。

## 3. 每栏内容清单

### 共享主干（画一次）

`三视角 CIR（90×189, abs-std 归一）` → `共享编码器 Eθ：双路径 · 每路径 4 层
pre-LN Transformer · 三视角权重共享` → `每视角两条 token 序列：时序 t=1…T(90) /
距离 r=1…M(189)` → `逐视角特征码 f_v = flatten(时序) ⊕ flatten(距离) + e_v,
dim 8928` → `闭集分类头（跨视角平均读出）→ k̂` → `逐视角检查器 η_k̂^(v)：
由 k̂ 选定，每 (类,视角) 一个，d_v = ‖η(f_v) − φ‖` → `开集异常分数 s(X)`。

补上了 §1.2 的第 3、4、5 点。

### (a) 瓶颈中层融合（插入点 ①）

绿色虚线框标题写死为 **「编码器第 4 层（最后一层）内部」**，框内：

- 三条视角 token 条（L/T/R）在左；
- 右侧一排 4 个紫色瓶颈 token，标 `N_B = 4`；
- 每条视角 token 与瓶颈之间画**双向**虚线（互相读写）；
- 瓶颈下方 `瓶颈跨视角取平均`，虚线回写到视角通路；
- 框内脚注：`瓶颈是唯一的跨视角通道，无两两稠密注意力` /
  `K = 1（仅最后一层）· 总深度不变` / `交换前先在 token 上注入视角身份`。

框外：`更新后的三路 token 仍分开读出 → 逐视角特征码`，以及一个小注框
`时序路径与距离路径各有一组瓶颈；两条路径都参与交换（与 (b) 栏不同）`。

**不再出现**「编码器后半段」。

### (b) 编码后特征级融合（插入点 ②）

- 顶部三条编码后**时序** token 条；
- 绿框「视角维自注意力：对每个慢时间索引 t，在 3 个视角之间做自注意力」；
- 框内画 3×3 注意力矩阵（行=查询视角，列=键/值视角）：对角实线彩色=自注意，
  非对角虚线=跨视角，图例说明；脚注 `9 个位置全部有权重：全带宽两两交互，
  无信息瓶颈`；
- 输出三条已耦合 token 条 → `同时喂闭集头与检查器`；
- 灰色虚线注框：`距离路径 token 不经过任何跨视角阶段，原样进入特征码 →
  两条路径在此不对称`。

补上了 §1.2 的第 6 点。

### (c) 决策级距离聚合（本文，插入点 ③）

- 三个独立检查器 `η_k̂^(L/T/R)` → 三个 `d_L / d_T / d_R`；
- 注 `三条通路在此之前从不相连`；
- 直角折线汇合 → 绿框 `跨视角距离聚合（式 12）`：
  `s(X) = mean_v(d_v)/σ̄ + β·var_v(d_v)/σ̄²`，下方小字 `σ̄ = 三视角类内尺度均值`；
- 两个并排小框解释两项：`第一项 · 多视角平均：几何互补 + 一致性去噪` /
  `第二项 · 跨视角分歧：三路应同时贴近各自原型`；
- 脚注 `β = 0 时退化为纯平均；V = 1 时退化为单视角判决`。

### 三栏底部

绿色结论条 + 一行数字（数字取自 `tab:fusion` 与 §5.3、RESULTS §22–23）：

| 栏 | 结论条 | 数字行 |
|---|---|---|
| (a) | 编码器内部窄通道交换 | 随机切分 OSCR 95.96 · LOSO 83.43 ± 8.45 |
| (b) | 编码后时序 token 全带宽交互 | 随机切分 OSCR 95.30 · LOSO 已落后，未纳入 |
