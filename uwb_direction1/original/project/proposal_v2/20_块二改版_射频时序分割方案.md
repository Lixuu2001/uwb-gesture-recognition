## 0. 一页结论

1. **这条路能走，而且比轨迹预测更好落地**——因为你单位已经有技术积累和工程能力，学位论文不用从零造。
2. **但有一条致命风险必须先拆**：时序分割的输出**仍然是"每一帧一个标签"**。导师上一轮判死块一的理由就是
   "输出全是标签"。**不做防守的话，这一版会被同一把刀砍第二次。** 防守方案见 §2，这是全文最重要的一节。
3. **数据能凑齐，但不完美**。目前**唯一**同时有"UWB + 相机 + 连续未剪辑流 + 标注"的公开数据是
   **OPERAnet**；纯 UWB 的补充是 Bocus 2022（CC0）和 UQAC 智能家居 ADL（和你同一颗 X4 芯片）。
4. **缝是开的**。查下来：扩散式时序分割全在视频域（DiffAct/DiffAct++ 都是）；射频域的时序定位用的是
   Mamba/TCN/Transformer（WiFiTAD、XRFMamba）；扩散在射频域只被用来做**数据增强**和**对比学习**，
   **没有用来做分割解码**。也就是说"扩散式分割 × UWB"这个组合我没查到现成工作。
   ⚠️ **检索非穷尽，正式立项前必须做一次正规查新。**
5. **建议的三点结构**：①建 UWB 时序分割基准与射频表征 → ②相机—UWB 互补与缺模态鲁棒 →
   ③在线因果分割与边界确认延迟。三点分别对应"能不能做""为什么非要 UWB""机器人能不能用"。
6. **最大的技术风险不在方法，在数据的"结构性"**：TAS 之所以强，靠的是动作之间有顺序结构
   （拿杯子→倒水→搅拌）。现有 UWB 数据只有 3–6 类、顺序很弱。**这一条不先量出来，后面全是空谈**
   （先导实验 Q1，见 §7）。

## 1. DiffAct++ 是什么（三句话）

用大白话讲：

> 传统做法是"看一眼视频，直接给每一帧贴标签"，一步到位，容易贴得零零碎碎。
> DiffAct 的做法是**先在纸上乱涂一通（纯噪声），然后一遍一遍地擦掉重画**，
> 每一遍都对照着视频内容修正，画个几轮，一条干净的时间线就出来了。

技术上：它把"逐帧标签序列"当成要生成的东西，用扩散模型从纯噪声开始迭代去噪，
每一步都以视频特征为条件。DiffAct++ 在此基础上加了两样：

- **一套掩码策略**，让模型分别学到三种先验——动作大概在什么位置（位置先验）、
  边界本来就是模糊的（边界模糊性）、动作之间有依赖关系（关系先验）；
- **一致性梯度引导**：推理时让"有掩码"和"无掩码"的输出尽量一致，等于给它多一层约束。

出处：*DiffAct++: Diffusion Action Segmentation*, **TPAMI 2025, 47(3):1644–1659**
（DOI `10.1109/TPAMI.2024.3509434`），前身是 DiffAct（ICCV 2023）。

**为什么这套机制搬到射频上是"对症"而不是"硬套"**：

| TAS 领域的老毛病 | 扩散式解码为什么正好治它 | 射频数据上会更严重吗 |
|---|---|---|
| **过分割**（把一段动作切成一堆碎片） | 迭代去噪天然是"由粗到细"，先定大结构再修细节，不容易碎 | **会，而且严重得多**——射频信噪比低、抖动大 |
| **边界说不准** | DiffAct++ 明确把"边界是模糊的"当先验来学 | **会**——射频看不到清晰的动作起止 |
| **不确定度没法表达** | 扩散天生能采样多次，看结果抖不抖 | 射频更需要这个（见 §5 的 2.3） |

这三条是这个方案能自圆其说的核心：**不是因为你手上有这个技术所以硬用，而是射频域恰好把
这个技术要解决的毛病放大了。** 写论文时这段就是 motivation。

## 2. ⚠️ 致命风险：时序分割的输出还是标签

### 2.1 风险到底在哪

导师的判据（记忆文件 `proposal-restructure-criterion`）是：

> **按"输出空间 + 评价指标"判是不是同一件事。三篇论文输出全是标签，所以方法换三次也算一件事。**
> **头条数字里不能出现分类准确率。**

时序分割的标准输出是**每一帧一个动作标签**，标准指标里的 **MoF（frame-wise accuracy）
就是逐帧分类准确率**。如果不做处理，导师完全可以说：

> "你这就是把手势分类改成逐帧分类，还是一件事。"

**这个风险是真实的、而且是高概率的。** 必须主动防守，不能赌他不问。

### 2.2 三层防守（按重要性排序）

**第一层：头条指标里禁止出现 MoF。**

TAS 的标准指标有四个，你只能把后三个放头条：

| 指标 | 是什么 | 能不能放头条 |
|---|---|---|
| **MoF / 帧准确率** | 有多少帧标对了 | ❌ **绝对不行**，这就是准确率，放上去等于自杀 |
| **Edit（分段编辑距离）** | 预测出的**动作顺序**跟真实顺序差几步 | ✅ 衡量的是结构，不是分类 |
| **F1@{10,25,50}** | 段级重叠够不够（按时间 IoU 判真阳） | ✅ 衡量的是段，不是帧 |
| **边界误差（秒）** | 每个转折点差了几秒 | ✅✅ **最好的一个，单位是秒，跟准确率毫无关系** |

**第二层：把"输出物"定义成时间线，不是标签。**

一条时间线包含：**边界在哪（时刻）、每段多长（时长）、顺序如何（结构）**。
论文里的主图应该是**一条彩色时间条**，不是混淆矩阵。失败方式写成
**"切碎了 / 边界漂了 / 顺序错了"**，不是"认错类别"。

**第三层（最强、也最有价值）：把时间线再往下游推一步，变成连续数值。**

时间线本身能导出一批**纯数值**的行为指标：

> 站立时间占比、行走时间占比、步频、最长连续行走段、起夜次数、如厕时长、久坐段数……

这些不是我编的——它们是文献里**已经验证过的体弱（frailty）数字生物标志物**
（*Digital Biomarkers of Physical Frailty*, PMC8401149：percentage time standing、
percentage time walking、walking cadence、longest walking bout），以及
**认知衰退的数字标志物**（IADL 作为认知衰退指标，*Neurology* P6-6.003）。

有了这一层，你的最终交付物是**一张行为量表**，全是连续数值。
导师再问"你的输出是不是标签"，回答是：

> 标签只是中间产物。最终输出是这个人一天的行为量化指标，用来做早期筛查。

**这一层建议写进论文的最后一节，不必做大规模临床验证，做出量表 + 演示即可。**

## 3. 痛点：现在的感知和具身智能缺什么

### 3.1 感知侧：现实世界不会把数据切好给你

这是最硬的一条，也直接洗白了你的块一：

> 块一（包括绝大多数射频感知论文）的做法是：**先人工把连续数据切成一段一段，每段一个动作，
> 然后做分类**。真实部署里根本没有人给你切。机器人和监护系统面对的是**一条永不停止的流**。

所以"把连续流切成有意义的段，并且定位边界"才是真任务。
**从"分类已切好的片段"到"分割未剪辑的流"，这是任务设定的升级，不是方法的换皮。**

### 3.2 具身智能侧：长时任务的"步骤感"是当前的卡点

现在的 VLA / 大模型能做单步操作，但长时任务（做饭、装配、护理流程）会出现
**子任务级误差累积和执行漂移**（*Safe Embodied AI for Long-horizon Tasks*, arXiv 2606.05660）。
机器人要接手、递工具、避让，前提是知道**人做到第几步了、这一步什么时候结束**。

这个方向 2025–2026 明显在热：
- **M2R2**（arXiv 2504.18662）：多模态机器人表征做时序动作分割；
- **RoboSubtaskNet**（arXiv 2602.10015）：从人的长视频里切出**机器人可直接执行的**子任务段，
  服务于"人教机器人"；
- 在线化也在推进：**O-TALC**（arXiv 2404.06894）专治在线分割的过分割，
  流式 TAS 也有强化学习方案（arXiv 2309.15683）。

**但这些全是视频。** 射频那一侧还没人把这条线接上去。

### 3.3 为什么非得是 UWB：相机的三个死角

| 死角 | 相机 | UWB |
|---|---|---|
| **黑暗 / 夜间** | 失效（红外也有限） | 不受影响 |
| **遮挡 / 穿薄墙** | 目标丢失 | 能穿家具、薄墙 |
| **隐私敏感区**（卧室、卫浴） | **法规和伦理上不能装** | 不成像，只有回波 |

反过来，UWB 单独也不行：分辨率糙，细粒度动作分不清。
**所以正确的姿势不是"UWB 取代相机"，而是"UWB 补相机的死角"** —— 这正好是 §5 的研究点 2.2。

## 4. 数据集（按时序分割的标准重新筛）

筛选标准变了。轨迹预测要的是"连续位置真值"，时序分割要的是：
**未剪辑的连续流 + 逐帧（或带精确边界时间戳）的动作标注 + 类别数量够多、顺序结构够强。**

### 首选

**OPERAnet** —— 目前**唯一**同时有 UWB 和相机的现成选择

- 被动 UWB CIR（Decawave 两套，12 条链路 + 5 模块）
- **同步的 Kinect v2 3D 骨架**（25 关节，10 Hz）← 这就是你要的"加相机"
- 另有 WiFi CSI、被动 WiFi 雷达（想做多模态对比也够）
- 6 名被试 / 2 房间 / **约 8 小时连续采集**
- 动作：走、坐下、从椅子起身、躺下、**从地上起身**、上身转动
- CC-BY 4.0，figshare collection `5551209`
- ⚠️ **待核实**：标注是否带精确边界时间戳（先导实验 Q1 第一件事）

**Bocus 2022（`19` 里的 A1）** —— 纯 UWB、真住宅、CC0

- 7 节点 / 21 条双向链路的**被动** CIR，真实住宅四房间
- 1.6 小时连续，**逐次测量都带活动标签**（含"无活动"段）→ 天然是未剪辑流
- 单文件 2.37 GB，**CC0**，已核实可下载
- ⚠️ 只有 3 类（坐/站/走）、1 名被试 → **顺序结构很弱，可能撑不起 Edit 指标**

**UQAC 智能家居 ADL** —— 类别最多，和你同一颗芯片

- 3 台 **XeThru X4M200**（**跟你现在的 UWB-Gestures 同属 Novelda X4**）
- 真实公寓，**15 种日常活动**各做 10 次，按真实生活作息的模式串起来
- 类别数最接近视频 TAS 基准（50Salads 17 类）→ **顺序结构最有可能成立**
- ⚠️ 数据组织形式与标注粒度**待核实**

### 参考对手（不是 UWB，但必须知道）

**XRF V2**（IMWUT 2025，arXiv 2501.19034，GitHub `aiotgroup/XRFV2`）
—— **射频侧时序定位的当前 SOTA，你的主要对手和参照系**

- **853 条连续动作序列，每条约 80 秒，共约 16 小时**，16 名志愿者，3 个环境
- **WiFi + 手机/手表/耳机/眼镜的 IMU + 同步视频**
- 动作有简单的（走、坐）也有复杂序列的（**做饭、吃药**）→ **顺序结构强**
- 他们的方法 XRFMamba：mAP@avg **78.74**，超过 WiFiTAD **5.49**
- ❌ **没有 UWB**

**它的意义有两层**：①证明"射频做时序定位"是个被认可的题目，你不是自说自话；
②给你一个现成的强基线去比。**可以考虑：主实验在 UWB 上做，另加一组 XRF V2 上的结果证明方法通用。**

### 查过但不适用

| 数据集 | 为什么不行 |
|---|---|
| **XRF55**（IMWUT 2024，55 类，39 人，WiFi+RFID+mmWave+Azure Kinect） | **定长 5 秒片段、无边界标注、无 UWB**。虽然论文声称"支持 action segmentation"，实际结构是单动作分类 |
| **RADHOME**（Mendeley，10 人，6 种动作转移，CC-BY） | **是 mmWave 不是 UWB**；1200 个样本、每个样本只含一次转移。可作"转移建模"的参考 |
| 穿墙运动状态、ALERT 车内、搜救等（见 `19` C 级） | 只有片段级类别标签，没有连续流 |

## 5. 新块二：三个研究点

**总题目（建议）**：

> **面向隐私敏感与遮挡场景的射频时序行为分割：从连续 UWB 流到行为时间线**

三点的分工是"**能不能做 → 为什么非要 UWB → 机器人能不能用**"：

### 2.1 UWB 时序分割基准与射频域表征

| | |
|---|---|
| 要回答 | 连续 UWB 流能不能被切成有意义的动作段？射频域的"逐帧特征"该怎么造？ |
| 为什么是问题 | 视频 TAS 都用 I3D 提好的特征当输入，**射频没有对应的东西**。这一步没有现成答案 |
| 做什么 | ①建立**第一个 UWB 时序分割基准**（数据划分、指标、基线全套）；②把 MS-TCN++ / ASFormer / DiffAct++ 全跑一遍；③设计射频域的逐帧特征提取（**这里能直接复用块一的编码器经验**） |
| 输出物 | 行为时间线 |
| 头条指标 | **Edit、F1@50、边界误差（秒）**（MoF 只进附表） |
| 贡献点 | 基准本身就是贡献（射频侧目前没有）；加上"射频特征该怎么设计"的经验结论 |

### 2.2 相机—UWB 互补与缺模态鲁棒（**全篇最能说服人的一点**）

| | |
|---|---|
| 要回答 | 相机在黑暗、遮挡、隐私受限下失效时，UWB 能顶住多少？两者怎么配合最划算？ |
| 做什么 | 双分支（UWB 一支、Kinect 骨架一支）→ 融合；**训练时随机丢掉某一路**，逼模型学会单靠 UWB 也能撑；测试时人为模拟"天黑了""被挡住了""隐私模式" |
| 和扩散的天然契合 | 扩散模型本来就是"在噪声里恢复结构"的。**把"某个模态缺失"当成一种更强的噪声**，这是个自洽的建模角度，不是硬凑 |
| 输出物 | **模态退化曲线**：横轴是相机可用程度，纵轴是分割质量 |
| 头条指标 | 各模态组合下的 Edit / F1@50，以及**退化幅度** |
| 为什么值钱 | 它把"为什么要 UWB"从口号变成了曲线。**这一张图就是答辩时最该放的图** |

### 2.3 在线因果分割与边界确认延迟

| | |
|---|---|
| 要回答 | DiffAct++ 是**离线**的（要看完整段才给答案）。机器人要边看边判，那要牺牲多少精度？多久才敢确认一个边界？ |
| 做什么 | ①改成**只看过去**的因果版 + 滑动缓冲；②利用扩散**多次采样**天然给出不确定度（跑 K 次，看边界抖不抖）；③画延迟—精度权衡曲线 |
| 输出物 | 在线时间线 + **每个边界的确认延迟和置信度** |
| 头条指标 | **边界确认延迟（秒）**、过分割率、延迟—精度曲线 |
| 与旧资产的关系 | 这一点和 `15` 的"因果状态估计"、`19` 的"预测可信度自审"**是同一个思路的延续**——只看过去、并且知道自己什么时候不可信。**旧方案的思想没浪费** |
| 对接具身 | 这正是 §3.2 那批工作（O-TALC、流式 TAS）在视频域做的事，射频侧还没人做 |

### 5.1 三点与导师判据的对照

| | 输出物 | 头条指标 | 失败方式 |
|---|---|---|---|
| 块一（已完成三篇） | 类别 / 拒识 | Acc、OSCR、AUROC | 认错类别 |
| 新 2.1 | 行为时间线 | Edit、F1@50、边界误差(秒) | 切碎了、顺序错了 |
| 新 2.2 | 模态退化曲线 | 退化幅度 | 缺了相机就崩 |
| 新 2.3 | 在线时间线 + 延迟 | **确认延迟(秒)**、过分割率 | 判得太晚、判得太抖 |
| 下游交付 | **行为量表**（连续数值） | 站立/行走占比、步频、最长行走段 | —— |

四行输出物、指标、失败方式两两不同 ✅，且**头条无一是分类准确率** ✅

## 6. 大致流程（五步，非技术版）

1. **切窗 + 编码**：连续 UWB 流按时间切成帧，每一帧压成一个特征向量。
   （这一步是射频特有的活儿，视频那边有 I3D 现成的，你这边要自己做）
2. **先粗判一遍**：一个常规主干（TCN / Transformer）给出每一帧的初步猜测，同时产出条件特征。
3. **扩散精修**：从纯噪声开始，**反复"擦掉重画"**，每一轮都参照条件特征修正，
   最后得到一条干净的时间线。（这一步就是 DiffAct++ 的核心，也是治过分割的地方）
4. **接入相机**：骨架那一支并进来，训练时**随机遮掉某一路**，逼模型学会单模态也能撑。
5. **改成在线**：把"能看到未来"的部分掐掉，只看过去，边跑边出结果，
   同时报告"我到第几秒才敢确认这个边界"。

评测对手：MS-TCN++、ASFormer、DiffAct++ 原版（视频域基线搬过来），
加射频侧的 WiFiTAD / XRFMamba（如果做 XRF V2 那组实验）。

## 7. 风险与先导实验（一周内，非常便宜）

### 7.1 最大风险：UWB 数据的"顺序结构"可能根本不存在

TAS 之所以强，靠的是动作之间有**强顺序结构**：Breakfast 有 48 类、50Salads 有 17 类，
做早餐必须"拿杯子→倒水→搅拌"。**Edit 分数衡量的就是这个顺序。**

但 OPERAnet 只有 6 类、Bocus 只有 3 类，动作之间**几乎没有必然顺序**。
如果结构不存在，那么：

> 扩散、关系先验、Edit 分数**全部失去发挥空间**，做出来会跟"逐帧分类 + 中值滤波"没区别。

**这是整个方案的生死线，必须第一个验。**

### 7.2 先导实验

| # | 做什么 | 判据 | 不过怎么办 |
|---|---|---|---|
| **Q1** | 把 OPERAnet / Bocus / UQAC 的标注拉出来画成时间条，算三个数：**平均段长、类别数、动作转移熵**，跟 Breakfast / 50Salads 对比 | 转移矩阵明显非均匀（存在偏好顺序），平均段长在合理区间 | 换数据（UQAC 15 类优先），或引入 XRF V2 做主实验、UWB 做迁移验证 |
| **Q2** | 拿"逐帧分类器 + 简单平滑"当地板，看 MS-TCN++ 能不能明显超过它 | 段级 F1 明显高于地板 | 说明数据没有时序结构可挖，方案要重新想 |
| **Q3** | 核实 OPERAnet 标注是否带精确边界时间戳 | 有边界时间戳 | 只能用"每次测量的标签"当逐帧标注，边界精度受限，要在论文里写清 |
| **Q4** | DiffAct++ 官方代码把输入换成 UWB 特征能不能跑通 | 能跑通、loss 正常下降 | 纯工程问题，不影响立项 |

**Go / No-Go**：Q1 + Q2 都过 → 正式立项；
Q1 过 Q2 不过 → 保留方案但降低对扩散的期待，重点转 2.2 多模态；
**Q1 不过 → 这条路在现有 UWB 数据上不成立**，要么换数据要么换任务。

### 7.3 其他要注意的

- **正规查新是硬要求**。§0 第 4 条的"缝是开的"来自有限次检索，**不是穷尽性结论**。
  立项前必须在 IEEE Xplore / ACM DL / Web of Science 上按
  "diffusion + action segmentation + radar/RF/UWB" 正式查一遍。
- **单位项目与学位论文的边界**要提前跟导师和单位说清楚：哪部分是单位的、哪部分是你的，
  数据和代码能不能用在学位论文里。**这件事越早说越好。**
- 不要在新数据上顺手做成"UWB 活动识别"（那又变回块一）。
  **判断标准很简单：主图是不是一条时间条。是 → 对；是混淆矩阵 → 走偏了。**
