# 21 痛点地图：感知与具身智能现在卡在哪，以及我们能下手的位置

**日期**：2026-08-01
**问题来源**：用户问"如果主方向是轨迹预测，时序分割是不是就白做了"，以及"先把领域痛点整理出来再挑"。
**本文职责**：①回答两条线的关系；②给出可核查的痛点清单（带出处）；③标出哪些我们真能碰、哪些只能嘴上说。
**与 `19`/`20` 的关系**：`19` 是轨迹路线、`20` 是分割路线。本文的结论是**两者不是二选一**，
应合成一条主线，见 §1 和 §4。

## 1. 先回答：时序分割白做了吗？没有，它是轨迹预测的上游

### 1.1 轨迹预测最大的技术病，正好是分割能治的

轨迹预测的核心难点不是"算不准"，是**同一段历史对应多个合理的未来**——人走到门口，可能进门、
可能转身、可能停下。模型如果只输出一条平均轨迹，那条轨迹哪个未来都不是。

**学界主流解法就是"先猜意图/目标/阶段，再条件化生成轨迹"**：

- **目标条件预测**（goal-conditioned）：先预测多个可能终点，再对每个终点生成完整路径。
  这种"由粗到细"的做法在高随机性场景里明显优于直接predict整条轨迹。
- **意图感知的扩散模型 IDM**（arXiv 2403.09190）：把不确定度**明确拆成"意图不确定"和"动作不确定"**，
  用**两个相依的扩散过程**分别建模。结论是"引入意图信息对扩散建模有益"，
  并且因为意图那一路降了维，**推理时间比标准扩散少三分之二**。

**时序分割输出的正是"此刻处于哪个阶段/动作"——这就是意图那一路的离散版本。**

### 1.2 技术栈还是同一套

| | 时序分割 | 轨迹预测 |
|---|---|---|
| 当前主力生成范式 | **扩散迭代精修**（DiffAct / DiffAct++） | **扩散**（MID / LED / IDM） |
| 要解决的共同毛病 | 输出零碎、边界模糊、不确定度没法表达 | 多模态、过度自信、覆盖与精度权衡 |
| 你手上的东西 | 单位的 DiffAct++ 工程经验 | `15`/`19` 已经写好的因果契约与概率评测口径 |

**一个技术栈，两个输出。** 这不是把两件事硬凑，是同一个生成框架的上下游。

### 1.3 正确的结构

> **分割 = 上游（他在做哪个阶段） → 轨迹 = 下游（接下来往哪走） → 校准 = 兜底（我准不准）**

而且这个结构自带一条**可证伪的预言**，这比"我把两个模块拼起来了"值钱得多：

> **加了阶段条件之后，未来分布的覆盖率应当变好、FDE 应当下降；
> 且改善主要出现在"阶段转换点附近"的样本上。**
> 若改善不集中在转换点，说明阶段条件只是多给了参数，没有提供机制。

这条预言可以直接写进预注册，跟你在 `17` 里做过的事一模一样。

## 2. 痛点地图（三层，均附出处）

标注含义：✅=我们的数据和方法真能做实验；🟡=能做但只能做半条；❌=只能在引言里讲，做不了实验。

### A 层 · 感知：传感器和表征本身的问题

| # | 痛点 | 证据 | 我们能碰吗 |
|---|---|---|---|
| **A1** | **视觉退化环境**。烟、尘、雾、黑暗下相机和 LiDAR 一起废——LiDAR 波长短，穿不透浓烟。现在的共识是必须靠多模态融合，混合方案才能到 85–92% 检测率 | 浓烟下的 LiDAR-Radar 融合里程计（arXiv 2403.17441）；退化鲁棒的 LiDAR-Radar-惯性里程计（arXiv 2403.05332）；灾难救援机器人综述（PMC12986560） | 🟡 UWB 物理上确实能穿，**但没有"UWB + 烟尘"的公开数据**，只能引文献论证，做不了对照实验 |
| **A2** | **遮挡与盲区**。人走到障碍后面就丢目标，等他重新出现往往已经太近。现在的解法很绕：拿旁人的行为当传感器、或者对不可见区域算可达集然后一律回避 | 用人当传感器做遮挡感知障碍预测（arXiv 2412.20376）；遮挡感知 MPC（arXiv 2211.09156）；遮挡场景的行人意图扩散模型（arXiv 2511.00858） | ✅ **UWB 的强项**（能穿家具和薄墙），而且 OPERAnet / Bocus 数据里本来就有家具遮挡 |
| **A3** | **隐私禁区**。卧室、卫浴是跌倒高发地，恰恰法规和伦理上不能装摄像头 | 见 `19` §3.1 | ✅ **UWB 独占**，且有真实住宅数据 |
| **A4** | **感知的过度自信**。现有做法常从真值直接迁到带噪感知，不考虑由此产生的过度自信；**缺少校准的感知概率和不确定度意识**被明确列为可靠性缺口 | 《Making Embodied AI Reliable》（arXiv 2606.03593） | ✅✅ **你的看家本领**（论文三整篇就是共形/校准） |
| **A5** | **射频域没有"通用逐帧特征"**。视频有 I3D 这种现成东西，射频没有对应物，每篇论文各造各的 | 见 `20` §5 的 2.1 | ✅ 这本身就可以立成一个研究点 |

### B 层 · 预测：时间维度上的问题

| # | 痛点 | 证据 | 我们能碰吗 |
|---|---|---|---|
| **B1** | **多模态评价可以作弊**。Top-k ADE/FDE 只要"撒一大片高熵分布"把空间全覆盖就能刷高分，看着覆盖了其实一点都不精确 | 《Recent Advances in Multi-Agent Human Trajectory Prediction》（arXiv 2506.14831） | ✅✅ **最好的下手点**。换成覆盖率 + 校准 + 能量分数，这套口径 `15` §0.2 已经写好了 |
| **B2** | **学术惯性**。常用数据集、指标、架构沿用多年，只部分反映真实导航需求；领域自己承认最需要变的是"**反映决策质量而非仅位移误差**的指标" | 同上 | ✅ 与 B1 同一件事的正面表述 |
| **B3** | **预测质量到底怎么影响导航**，长期是拍脑袋。2026 年才有人专门研究"人体运动预测质量如何塑造受限空间中的社交导航性能" | HRI 2026，DOI `10.1145/3757279.3788664` | 🟡 我们没有机器人，做不了闭环导航实验；**但可以做"提前量—保护距离"的解析换算**（见 C3） |
| **B4** | **长尾泛化差、可解释性差、依赖大规模标注** | 行人轨迹预测综述（PMC12694338）；自动驾驶轨迹预测的进展与局限（arXiv 2503.03262） | 🟡 数据规模不允许我们谈长尾 |
| **B5** | **意图与动作的不确定度纠缠在一起**，导致真实分布难以参数化 | IDM（arXiv 2403.09190） | ✅✅ **这正是"分割 + 预测"合流的理论依据**，见 §1 |

### C 层 · 具身/决策：机器人拿到感知结果之后

| # | 痛点 | 证据 | 我们能碰吗 |
|---|---|---|---|
| **C1** | **不确定度传不到规划里**。这两年才开始用共形预测给预测轨迹套不确定域，让规划器有据可依 | 共形不确定度处理的人群导航（arXiv 2508.05634）；SoNIC 用自适应共形推断量化行人预测不确定度 | ✅✅ **你的论文三资产直接对口**，是三块资产里复用度最高的 |
| **C2** | **长时任务的子任务级误差累积**。每一步局部看都对，风险悄悄攒着，最后以物理安全事故的形式爆发 | 《Safe Embodied AI for Long-horizon Tasks》（arXiv 2606.05660） | 🟡 分割这条线正好对口，但我们只能做"人的行为阶段"，做不了机器人操作 |
| **C3** | **人机协作的安全距离被迫过度保守**。ISO/TS 15066 的保护距离要把**测量不确定度、系统延迟、控制频率**全部计入——**越不确定，距离越大，产能越低** | ISO/TS 15066 的 SSM 实施（PMC5117641）；不确定人体状态估计下的安全时间最优规划（arXiv 2210.11655） | ✅ **最能把价值量化的一条**：预测提前量 + 校准的不确定度 → 保护距离能缩多少 → 这是一条可以算出来的曲线 |
| **C4** | **可靠性的四大挑战**：不完美感知带来的不确定、人类行为不可预测、开放世界让 ML 模块失效、模块间的涌现行为 | 《Making Embodied AI Reliable》（arXiv 2606.03593） | 前两条 ✅，后两条 ❌ |
| **C5** | **具身系统整体仍然脆弱**，尚未内化风险与危害的概念；安全评测受限于"不能做真实伤害实验" | 《Safety in Embodied AI》（arXiv 2605.02900） | ❌ 太大，只能引言里提 |

## 3. 诚实说明：哪些痛点我们只能"讲"，不能"做"

这一节是为了避免重蹈覆辙（记忆文件 `verify-data-before-claiming`：先核实再断言）。

| 讲得动但做不了 | 为什么 |
|---|---|
| 烟尘/浓雾下的感知（A1） | **没有 UWB + 烟尘的公开数据**，一条都没有 |
| 闭环导航性能提升（B3） | 没有机器人，做不了闭环 |
| 多人密集交互 | 被动 UWB 多人分离本身就是未解难题，OPERAnet 有人数计数但不是密集交互 |
| 细粒度操作理解（拧螺丝、抓取） | UWB 分辨率根本不够 |
| 跨人泛化 | 主数据集单被试（已在 `19` §8.1 决定不做） |

**写作纪律**：这些只能出现在引言的"背景与动机"，**绝不能出现在贡献列表和结论里**。

## 4. 建议下手的位置：一条主线，三个点

综合"痛点真实性 × 数据可得性 × 你已有资产"三项，我推荐这条：

> **主线：在相机失效或不可用的条件下，给机器人/监护系统一个带校准不确定度的短时人体行为预测。**

它同时踩中 A2（遮挡）、A3（隐私）、A4（过度自信）、B1（评价作弊）、B5（意图与动作纠缠）、
C1（不确定度传不到规划）、C3（保护距离过保守）——**七条真实痛点，且每条都有出处**。

### 三个研究点

| | 要回答 | 输出物 | 头条指标 | 对应痛点 | 复用的资产 |
|---|---|---|---|---|---|
| **2.1 射频流的行为阶段分割** | 连续 UWB 流能不能切成有意义的阶段？射频的逐帧特征怎么造？ | **行为时间线** | Edit、F1@50、**边界误差(秒)** | A5、C2 | 单位的 DiffAct++；块一的编码器经验 |
| **2.2 阶段条件的概率轨迹预测** | 加了"他正处于哪个阶段"这个条件，未来分布是不是真的变好了？改善是否集中在转换点？ | **未来轨迹分布** | ADE/FDE、**覆盖率、能量分数**（禁用可作弊的裸 Top-k） | B1、B2、B5 | `15`/`19` 的因果契约与 P0b 运动学基线 |
| **2.3 预测可信度的校准与失效自审** | 部署时没有真值，系统能不能自己知道"这一段我不可信"？不确定度能不能缩小保护距离？ | **可信区间 + 拒绝判据 + 保护距离曲线** | 覆盖率、风险—覆盖曲线、**保护距离能缩多少** | A4、C1、C3 | **论文三的共形整套** |

串起来是一句话：**看到 → 判断他在哪个阶段 → 预测他往哪走 → 并且知道自己准不准。**

### 为什么这个切法比前两版都好

1. **三块资产全用上**：块一的编码器、论文三的共形、单位的 DiffAct++。没有一块闲置。
2. **导师那把刀砍不动**：三个头条指标分别是"秒""覆盖率/能量分数""保护距离"，**没有一个是准确率**。
3. **应用价值能算成数**：2.3 的保护距离曲线是可以从 ISO/TS 15066 的公式直接推的——
   **提前量多 0.5 秒，保护距离能缩多少厘米**，这是能写进摘要的一句话。
4. **不确定度这条线贯穿三点**，正好是 A4 + C1 这个"领域自己承认的缺口"。

## 5. 下一步

按依赖顺序，只有两件事是真正的未知数：

1. **数据里到底有没有"阶段结构"**（`20` §7 的 Q1）。没有结构，2.1 就是空的，2.2 的条件也无从谈起。
   → 把 OPERAnet / Bocus / UQAC 的标注画成时间条，算段长、类别数、转移熵，跟 Breakfast / 50Salads 比。
2. **能不能从被动 UWB 反演出可用的连续轨迹**（`19` §6 的 P1）。反演不出来，2.2 就没有预测对象。
   → Bocus 数据 CC0、2.37 GB、真值内置，直接跑。

**这两件事互相独立，可以同时做，都是一两天的量。** 两件都过 → 这条主线成立；
只过 1 → 退成纯分割（`20`）；只过 2 → 退成纯轨迹（`19`）。
