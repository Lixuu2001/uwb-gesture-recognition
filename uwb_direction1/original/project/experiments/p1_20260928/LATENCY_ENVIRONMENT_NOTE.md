# 本机延迟测量的环境补充

记录于 2026-09-29（北京时间），在任何有效 CUDA 计时结果产生之前。

首次 CUDA smoke 在环境检查阶段退出，尚未进入模型加载和计时。两项原因：Python 以本机 GBK 解码 PowerShell 进程 JSON，而实际输出含不兼容字符；NVIDIA 在 WDDM 下把 QQ 的长期桌面 C+G 上下文列入 compute-apps，原检查把这个上下文直接当作活跃计算任务。

根因检查：显式令 PowerShell 输出 UTF-8，并令 Python 按 UTF-8 严格解码后，得到有效的 517 行进程 JSON。QQ.exe 的 PID 为 52016，进程创建于 2026-09-20；连续二十余秒的 nvidia-smi 观测中 GPU 利用率为 0%，总显存约 27 MiB，功率约 1.7 W。仅凭上下文存在不能判断正在训练，也不能据空闲时采样保证之后绝无桌面干扰。

修复保留默认拒绝其他 GPU 计算进程的行为，仅增加操作者显式指定单个空闲桌面 PID 的入口，本轮指定 52016。已知训练任务、Python 计算进程及新增的未列明 GPU PID 仍会阻断运行。对允许的桌面进程记录并复核身份；身份改变则停止。

存在该例外时，每折计时前后均记录 5 个 GPU 利用率样本（约 1 秒间隔），最后 3 个须不超过 5%；读数不可用或持续繁忙则停止。前两个读数用于容纳本脚本刚完成计算的利用率窗口残留。阈值不是可调超参数，不根据延迟结果修改。该检查只确认采样窗口空闲，不提供独占设备或全程无干扰保证。

使用同一组 279 个预定片段、相同样本内随机方法顺序和原计时边界；模型、策略、价格、阈值、精度和停止门槛不变。报告将明确这是保留空闲桌面上下文的本机处理延迟测量，保留 mean/median/p95，不声称专用部署设备的保证时延。此补充不修改 LATENCY_PROTOCOL.md，随新 benchmark 源版本一起绑定记录。
