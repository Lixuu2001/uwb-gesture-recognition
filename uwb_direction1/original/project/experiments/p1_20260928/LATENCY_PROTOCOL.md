# 推理耗时测量协议

2026-09-28，正式多雷达八折仍在训练，预算和策略测试结果尚未汇总。此处冻结测量边界，不按性能挑选有利计时方式。

- 使用本机 RTX 4060 Laptop、当前 PyTorch/CUDA 环境，batch=1、eval、BF16 autocast、MATH attention；禁用 TF32、固定 CPU 线程。GPU 训练全部停止后计时，记录设备、线程和环境，不将训练竞争下的延迟当作部署性能。
- 输入边界为原有 `cache/X_clutterremoved.npy` 中已去静态杂波的单条 90×189 片段。包含幅度/解析相位运动生成、逐片段标准化、float16 打包、CPU→GPU、真实请求视角编码、融合与输出传回 CPU；策略还包含概率计算、CPU 决策和增量融合。排除传感器采集、原始文件读取、此前的杂波去除及一次性的模型加载；这些排除项必须随数字一起说明。
- 先从原脚本提取并复用 `norm/transform/_analytic/doppler_map`，检查新生成输入与冻结 prepared off/only 的 float16 值逐位一致。禁止为提速改成不同预处理。
- 计时前后显式 CUDA synchronize；报告端到端 mean/median/p95 和实测处理路数。每条动作的所有数据已存在主机内存，但只允许读取并变换请求视角。已算视角特征缓存复用，追加时只编码新增视角。
- 各测试用户每个存在类别，按固定 RNG(44000+fold*100+class) 选3条，共279条代表性片段；每种策略同一组片段。每次模型加载后至少10次预热，计时路径顺序固定随机打乱以减少温度/顺序偏差。模型参数按对应外层折加载。
- 固定模型测一/二/三路（一路和两路使用各折验证选择）；若条件策略未执行，也测已冻结的主置信度/熵级联。若策略执行，另测 class-gain 和 ExtraTrees 路由。固定单雷达 Right 模型作为独立训练体系的参考，不能将它与缺失视角模型的一路混成同一个模型。
- batch=1 与正式离线 batch=16/32 的浮点执行形状不同，允许报告因数值差异导致的预测/路由变化，不能据此改价格或阈值。计时集合很小，只作延迟测量，不替换全部测试用户的主性能指标。直接按需路径必须与相同 batch=1 的离线缓存重放一致；若不一致，先修复实现并重新测量。
- 90帧、20Hz 对应约4.5秒已采集动作。延迟数字从片段已可用开始，不能声称全过程实时、因果前缀识别、采集或硬件功耗节省。总延迟没有降低时，不以少处理一路推断实际更快。
