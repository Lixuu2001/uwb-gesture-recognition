# 多视角辅助跨人元训练：建议核查与下一轮方案

日期：2026-09-08。状态：已完成 8 组公共初始化和 A0–A3 × 8 用户的 32 组正式实验，独立审计与全部单 Right 部署重放通过。A3 相对 A1 准确率差为 −0.073 个百分点，0/8 用户改善，未达到预设开发门槛；停止扩大当前固定配置。详见 [完整结果](runs_s2026/RESULTS.md) 与 [完成记录](COMPLETION.md)。

## 建议采用的主线

优先检验“多视角带来的参数更新，是否有利于另一位训练用户的单 Right 识别”。这与此前的缺失视角联合分类不同，值得做一轮受控筛选，但现有文献不保证它能提高本数据集准确率。

当前端到端缺失视角实验为 R 74.497%、MV 74.520%，配对差 +0.023 个百分点，未超过原始分类器 74.773%。本轮不修改这批结果，也不通过延长其训练或叠加损失来重新解释它。

## 已经完成的核查

### 1. 真实三视角模型的误差互补

直接重算已有 `teacher_concat_s2026_h*_predictions.npz` 与 `sv_R_label_global_s2026_h*_predictions.npz`。八折 train/val/test IDs 与标签均匹配，保存类别与 logits argmax 一致。下表均为用户等权结果，U、H 的分母是全部测试样本。

| 指标 | 结果 |
|---|---:|
| 原始 Right 分类器准确率 | 74.773% |
| 已有真实三视角分类器准确率 | 92.270% |
| U：Right 错、真实三视角对 | 19.275% |
| H：Right 对、真实三视角错 | 1.777% |
| 两者均错 | 5.952% |

每折均满足 Acc(MV)-Acc(R)=U-H。用户 6 的 Right/真实三视角分别为 55.182%/75.727%，两者均错的比例仍为 21.636%。

这是已有两种系统的错误互补诊断：真实三视角模型使用幅度输入和三视角拼接分类头，Right 使用幅度加相位运动输入，两者容量也不同。因此，差值不是隔离后的“增加视角因果收益”，更不是单 Right 的可迁移上界。这里的 92.270% 也不是刚完成 E2E_MV 的完整三视角推理结果。

### 2. 共享 BatchNorm 风险未在当前实现中发现

当前编码器使用 Transformer 的 LayerNorm，分类头没有 BatchNorm。输入标准化按样本、按视角进行；E2E 特征 mean/std 按视角保存，Right 推理明确使用 Right 统计。因此不能把这次失败归因为已证实的三路 BatchNorm 混合。

依据：`vendor/uwb_osr/model.py`、`pipeline.py::norm`、`missing_view_fusion/data.py::fit_scale`、`missing_view_fusion/e2e/model.py::forward`。

### 3. 相位通道已有差分和幅度加权

实际计算为快时间 Hilbert 解析信号，减去整段静态分量，再计算 `angle(z[t] * conj(z[t-1])) * sqrt(abs(z[t] * conj(z[t-1])))`，最后按样本/视角标准化。不是直接输入未经处理的绝对相位，也不能称为标定径向速度。

尚未使用 sin/cos 周期编码；取 angle 后仍有 ±π 表示边界。是否形成主要问题需要数值分布和独立输入消融支持，不能仅凭代码中出现 angle 就断言故障。本轮 A0–A3 保持现有输入。

### 4. 主体验证必须覆盖预训练全过程

旧协议是七位训练用户各自留 10% 样本验证，外层测试用户独立。旧结果不存在由此自动成立的测试泄漏，但验证选择没有直接模拟整位未见用户。

下一轮改成六位用户训练、一位用户验证、一位用户测试时，不能继续加载旧七用户检查点：新验证用户已参与旧模型的参数训练。旧全局标签平滑矩阵、特征归一化统计等训练派生量也不能照搬。应保留原 Right 网络结构，在新的六用户集合内重建公共初始化与所需统计。

## 网络与数据流

部署路径保留原始 `Classifier([2], 'concat', 'mean')` 的编码器、时空 token 展平和原分类头，不再改成上一轮的小型缺失视角读出头。

训练增加一个小型三视角辅助分类分支，共享编码器。Left/Top/Right 只用于训练支持集的辅助监督。实际验证、外层测试和部署均直接走原 Right 分类路径，不输入其他雷达，也不对新用户执行参数更新。

每一步在六位参数训练用户中轮换一位作为 query 用户，另外五位作为 support 用户：

1. support 用户的 Right 数据计算基础分类损失；A2/A3 同时使用这五人的同步三视角计算辅助分类损失。
2. A1/A3 以 support 损失做一次虚拟更新，不修改正式参数或优化器状态。
3. query 用户只提供 Right 数据，用更新后的模型计算分类损失。
4. 用 support 与 query 目标更新正式模型；下一步轮换 query 用户。

query 用户仍然是合法的训练用户，会在其他步骤承担 support 角色。它不等于真正的验证或外层测试用户。

## 四组必要对照

| 组别 | support 目标 | query 的 Right 目标 | 回答的问题 |
|---|---|---|---|
| A0 | Right 分类 | 在原参数上计算 | 新主体验证协议下的原 Right 架构基线 |
| A1 | Right 分类 | 在虚拟更新后计算 | 模拟换人本身有没有用 |
| A2 | Right + 三视角辅助分类 | 在原参数上计算 | 同辅助分支的普通联合训练有没有用 |
| A3 | Right + 三视角辅助分类 | 在虚拟更新后计算 | 三视角更新是否更有利于跨人识别 |

A0/A2 也读取与 A1/A3 一样的 support/query 用户及样本，两部分样本均参与普通分类目标；不能让元训练组多看一批训练数据。四组保持相同主体/类别采样规则、Right 损失、初始化和选模型规则；A2/A3 辅助分支也同初始化。

核心差值为 A3-A1、A3-A2、A3-A0。进一步报告交互差 `(A3-A1)-(A2-A0)`，判断多视角与跨人训练结合后是否带来超出各自变化的收益。若只有 A1 优于 A0，则应归为单视角跨人训练收益。

## 元梯度实现的边界

原始 MLDG 目标需要对虚拟更新继续求导，论文明确涉及二阶导数。对目标作一阶 Taylor 展开，不等于实现时截断内更新梯度仍然保留全部同样的优化性质。

建议先实现一步可微内更新，用小网络的数值梯度检查核对，并在当前 GPU 上测量显存和耗时。重点确认 query 损失能经“虚拟更新”影响共享编码器及多视角辅助参数；内更新不得只改一个与部署编码器无关的头。

如果资源测试需要改用一阶近似，必须明确记录为近似版本，并采用梯度回传到正确初始参数的实现。不能把断图后只训练临时副本、或退化成普通两项损失相加的代码称为原始 MLDG。任何近似版负结果只约束该版本。

## 执行顺序与规模

1. 固定八折的 train/validation/test 主体清单。建议 test=h、validation=(h mod 8)+1，其余六人训练；该映射只依据编号，与历史用户准确率无关。它是资源受限的固定内层主体验证，不冒称穷举全部嵌套组合。
2. 在各折六位训练用户内从头训练公共 Right 初始化，重新计算需要的平滑统计；四个分支从同一权重出发。A0 也获得同样的后续训练预算，避免比较“继续训练”与“没有继续训练”。不加载任何见过外层测试或验证用户的旧权重。
3. 完成虚拟更新梯度、参数恢复、用户隔离和单 Right 部署检查。用短程运行测显存与实际耗时，冻结训练预算、优化器和停止规则；短程外层测试结果不用于选择配置。
4. 固定一个模型种子完成 A0–A3 的八折开发性比较：32 个分支训练，加 8 个公共初始化。首版不叠加 Group DRO、时序对齐、风格增强或原型库。不按途中某一测试用户的涨跌改变方案。
5. 重算逐用户/逐类指标，比较 A3-A1/A2/A0、较差用户表现、参数更新及计算成本。四组按相同样本暴露/正式更新预算比较，额外报告虚拟更新的前后向与耗时；相同 epoch 不冒称相同算力。

新的 A0 可能低于或高于 74.773%，因为训练用户数量和选模型规则改变了。方法贡献必须用新协议中的配对差说明；74.773% 只保留为历史参考，不能把跨协议差值全部算作方法提升。

## 投入门槛与下一步分流

沿用 +2 个百分点、至少 6/8 用户改善的开发投入门槛，主比较设为 A3-A1，并要求 A3 平均表现优于同协议 A0 和 A2。通过后追加第二初始化及同用户同类别的跨视角错配控制；未通过则停止该配置的大规模扩展。

阶段对齐排在后续：先确认三路时间对应的可靠程度。粗运动起止或互相关一致只能支持粗对齐，不能证明硬件逐帧同步。阶段对齐必须与 Right-only 对齐比较。

风格干预作为另一候选：当前输入已按样本/视角标准化，简单的整体幅度缩放可能被抵消；MixStyle 原始实现基于 CNN 特征统计，不能直接把其张量轴和结论套到当前 Transformer。应先确认扰动在目标层确实存在、不会被后续归一化抵消，再比较 Right-only、三视角独立扰动与一致扰动。

八位用户已参与多轮开发，重新分离主体验证不能消除这段历史。没有独立新用户数据时，所有结果继续标为当前数据上的开发性跨人评估。
