# 同类跨用户低强度统计增强：完成记录

2026-09-09。本轮实现、训练和独立审计已完成。新训练八个 STYLE 模型；复用并重新核验上一轮在相同当前环境训练的八个 CONTROL。共十六组模型产物全部核验通过。

**结论：当前固定统计增强没有带来整体提升，停止这一配置的扩展调参。** 用户等权准确率从 71.2913% 降到 70.6646%，变化 −0.6267 个百分点；宏 F1 从 70.1895% 降到 69.6056%，变化 −0.5838 个百分点。只有 2/8 位用户改善，未达到“平均至少 +2 点且至少 6/8 位用户改善”的预设开发门槛。

准确率变化的描述性用户配对 bootstrap 95% 区间为 [-1.6184, +0.0250] 个百分点。该区间跨过零，因此不将这次均值下降解释为所有同类统计增强都必然有害；当前结果已经足以停止这一固定设置。

## 本轮具体做了什么

仅输入 Right 雷达。每个训练样本以 25% 概率使用统计增强，混合份额为 10%。供体必须在本折六位训练用户中，与源样本手势类别相同、用户不同；先均匀选可用供体用户，再选该用户的同类实例。验证和测试均保持干净输入。

增强放在时间、空间两条路径的线性输入投影之后、位置编码之前。两条路径共用供体和启用掩码。按通道混合序列均值和总体标准差，统计用 float32 并停止梯度；供体仅经过当前线性投影，无供体编码器训练或随机层。未启用样本保持逐值不变。训练 hook 在每轮结束及异常退出时移除，导出模型仍为原始 Right 分类器。

设计借鉴 [MixStyle 论文与官方实现](https://github.com/KaiyangZhou/mixstyle-release) 的特征统计混合思路。同类跨用户供体、固定小份额和双路径插入位置是本项目的具体选择，不能认为原论文已经验证这些设置适用于雷达。统计差异也不等同于纯用户风格。

时间增强未与本方法叠加，模型、损失、学习率、初始化和批次顺序沿用原流程。供体与掩码使用独立随机序列，不改变模型/dropout/sampler 的随机状态。

## 数据与对照有效性

质量筛选保留 9,300 个实例、8 位用户。每折六位用户训练、一位完整用户验证、一位完整用户测试。模型种子为 2026；最多 40 轮，按干净验证集 CE 的首次最小值选择模型。

CONTROL 来自 mild_time_augmentation/runs/CONTROL，并非重新训练了十六个模型。复用前核对了原代码、来源快照、数据、Python/NumPy/PyTorch/CUDA、配置和各模型文件；逐折核对完整用户划分、OOF 平滑矩阵、初始化及采样。当前 NumPy 为 2.0.2，与这组 CONTROL 完全一致。

平滑矩阵检查重构保存的 OOF 概率对应矩阵并核对拟合/预测用户隔离，没有重新拟合全部 OOF 代理模型。历史约 74.77% 的训练/验证协议不同，不能直接与本轮数值相减。

## 结果如何理解

逐用户准确率变化为 −0.5833、+0.6000、−0.3333、−3.8333、+0.1667、−0.3636、−0.3333、−0.3333 个百分点。第四位用户下降最大。该折 CONTROL 与 STYLE 分别按验证集选中第 8 轮和第 3 轮模型；选择规则完全相同，不能仅凭这项观察断言下降由哪个机制导致，更不能回头用测试结果重选模型。

与上一轮使用相同 CONTROL 的温和时间增强并列看：时间增强 +0.9222 点、6/8 改善；统计增强 −0.6267 点、2/8 改善。两项固定设置均未达到预设开发门槛。本轮保留实现、模型和逐样本证据，不将统计增强替换为默认训练方案，也不据此启动组合调参。

这些用户数据已用于前期开发，且训练折相互重叠、只有一个模型种子。本结果是固定开发协议的实测结果，不是新用户现场泛化或三视角知识贡献的证明。
