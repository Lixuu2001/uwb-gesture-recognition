# 可训练编码器的单雷达部署实验

本目录验证第一条路线：训练时同时分类 R、LR、TR、LTR 四种视角组合，能否改善部署时仅 Right 雷达的识别。编码器与融合头共同更新。研究设计见上一级 `E2E_PLAN.md`，资源选择见 `RESOURCE_CHECK.md`。

2026-09-08 正式 16 个模型已完成并通过审计及全量部署复现。MV 准确率 74.520%，匹配 R 对照 74.497%，差值 +0.023 个百分点，未过投入门槛。详见 `COMPLETION.md`。

## 对照和结论范围

`E2E_R` 只读取 Right 信号；`E2E_MV` 在训练样本上读取同步三视角。两组每折使用相同初始编码器、新分类头、训练统计量、数据划分和采样顺序。两组均以单 Right 验证损失选择模型，外层测试与部署仅输入 `[B,1,90,378]`。

正式首轮为 8 个留一用户折、模型种子 2026，共 16 次运行。最少 12 轮、最多 40 轮、耐心 8 轮；选中最后几轮的模型只能说明受当前训练预算约束，不能声称充分收敛。

只将完整配对结果用于投入判断：相对 E2E_R 的等用户平均提升至少 2 个百分点，至少 6/8 用户改善，同时超过原始冻结分类器。这个门槛不是统计显著性检验。通过后仍需第二初始化和同用户同类别错配配对控制。本轮不能替代另外两条路线的端到端验证。

## 执行与恢复

```powershell
D:\D_conda\envs\pytorch\python.exe experiments/p1_20260905/missing_view_fusion/e2e/train_e2e.py --microbatch 128
```

正式输出为 `runs/`；`smoke/` 和 `smoke128/` 只用于流程和资源检查，不计入结果。训练按每折 R、MV 的次序运行。`queue_status.json` 记录队列位置，各组 `status.json` 记录运行状态。

每轮保存模型、优化器、随机数及采样状态。中断后使用同一命令恢复；恢复前核对配置与源码身份，已完成结果核验后跳过。源码变更需要新的输出目录。运行期间不应同时启动第二个正式训练进程。

## 单雷达部署

`deploy.load_deployment(checkpoint, device)` 直接加载 `deployment.pt`，只依赖网络架构源码，不读取训练检查点、标签矩阵、特征缓存或标签。返回模型固定为推理模式；`deploy.predict_logits(model, right, batch=128, precision='bf16')` 可在 CUDA 上按训练评估精度推理，CPU 可用 `precision='fp32'`。

输入是完成原项目预处理后的幅度＋相位表示，绝非原始 ADC 数据。精确复现正式保存预测时，还需与训练评估保持相同的输入量化（预处理数组转 float16）、设备、BF16 autocast 和批大小 128。跨设备或不同精度的误差应单独记录，不能把数值接近写成逐位一致。

数据使用固定 2026 划分，验证样本来自训练用户内部。八位用户已多次参与方法开发，因此这是受控的开发证据，不能作为全新外部人群的确认结果。
