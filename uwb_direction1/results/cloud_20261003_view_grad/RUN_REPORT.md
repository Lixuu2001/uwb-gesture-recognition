## 范围和结果

复用六条源用户3–8的四训练/一验证/一诊断轨迹。取固定第1/12/24轮**轮内密集平均**，不按验证结果选择。每条轨迹只抽其实际四个训练用户各96条，同一384条跨三检查点复用。共18检查点、216批、每检查点组2304次ID使用、跨轨迹2035唯一原ID、三时点合计6912样本呈现；没有用各轨迹验证/诊断行计算梯度或准确率，也没有分析用户1/2。

只有一个融合CE。每个视角的贡献是从该CE沿各自编码路径反传到共享encoder参数的链式梯度，并非三个任务损失。统计包括全部42,976个encoder参数，排除融合头；eval模式关闭Dropout，用float64测量而不更新权重。

“冲突批次”定义为三对余弦中至少一对≤−0.1；一条轨迹需至少两个固定时点中有≥50%批次满足，整体需≥4轨迹。单路主导定义为最大梯度范数占比≥80%，持续性规则相同。

## 数值失败、修复与审计

首轮float32在held3/第12轮/第6批（0起始）发生求和重构相对误差1.1857e-5，超出预设1e-5容限。绝对误差仅4.71e-8以下，但未忽略失败；保留FAILED_FLOAT32.log、NUMERICS_REPAIR.json。相同权重和输入转float64后误差1.0051e-15，因此统一提高计算精度，不放宽质量筛查标准。

最终全部216批的分路径梯度之和与原共享梯度相对误差最大1.10e-15以下。每检查点首批另深拷贝三个独立encoder求导，18组logits及路径梯度逐位一致。后审计重算保存首批的18组Gram矩阵（最大绝对差3.67e-15以下），以及全部批次统计/门槛、源ID和18模型SHA；通过。不能扩大为全部216次反向都用独立副本重跑。

float64成本估计422.99秒，实际369.20秒，低于600秒预算；实际时间排除输入整文件哈希、补充阅读、先前失败和后审计。没有新训练、分类评分或新训练检查点。原数组和既有权重不提交Git。
